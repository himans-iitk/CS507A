\title{What We Tell the Agent but Not the Newcomer}
\subtitle{Mining Agent Context Files for Gaps in Human Onboarding Documentation}

\author{Himanshu Mishra}
\affiliation{\institution{University of British Columbia}\city{Vancouver}\country{Canada}}
\email{himishra@student.ubc.ca}

\begin{abstract}
Coding agents such as Claude Code, Codex and GitHub Copilot read a repository context file that
tells them how to build, test and change the project --- knowledge a human newcomer needs just as
much. We measure how much of it is given only to the agent. For \nSampleRepos{} repositories
(\nPerAgent{} per agent file type), we compare \nQueued{} sections of the agent file with the
README and CONTRIBUTING at the same commit. On average, \agentOnlyOverall{} of a repository's
agent-file knowledge is absent from its human documentation and only \sharedOverall{} is fully
shared. The gap is about \emph{how to work on} the project: \needGroupTopShare{} of it concerns
processes and practices, led by \needTopOne{} and \needTopTwo{}. A simple TF-IDF detector finds
agent-only knowledge with F1 \detectorFOne{} on held-out repositories. We release the dataset,
codebook, pipeline and detector.
\end{abstract}

\section{Introduction}

Coding agents start every session by reading a context file --- \texttt{CLAUDE.md},
\texttt{AGENTS.md} or \path{.github/copilot-instructions.md} --- that explains how the project is
built and tested, how its code is organised and which conventions to
follow~\cite{chatlatanagulchai2026agentreadmes,mohsenimofidi2026context}. That is what a newcomer
needs too: people joining a project struggle to learn its structure and unwritten
rules~\cite{dagenais2010landscape}, and poor documentation is among the barriers they report most
often~\cite{steinmacher2015barriers}. A \texttt{CLAUDE.md} may say ``run \texttt{make verify}
before committing; never edit \texttt{src/gen/}'' while \texttt{CONTRIBUTING.md} says only ``PRs
welcome''. If this is common, projects onboard their agents better than their people. We ask:

\begin{itemize}
\item \textbf{RQ1:} How much agent-file knowledge is absent from the README and CONTRIBUTING?
\item \textbf{RQ2:} Which newcomer needs and barriers does this knowledge address?
\item \textbf{RQ3:} Can agent-only knowledge be detected automatically?
\end{itemize}

\begin{tcolorbox}[colback=black!3,colframe=black!35,boxrule=0.4pt,arc=1pt,left=4pt,right=4pt,top=3pt,bottom=3pt]
\small\textbf{Key findings.}
\begin{itemize}\setlength{\itemsep}{1pt}\setlength{\topsep}{2pt}\setlength{\leftmargin}{1em}
\item \textbf{RQ1:} \agentOnlyOverall{} of a repository's agent-file knowledge is agent-only;
\anyGapOverall{} is not fully available to people. \catHighOne, \catHighTwo{} and \catHighThree{}
knowledge is most often agent-only, \catLow{} least (\catLowShare).
\item \textbf{RQ2:} \needGroupTopShare{} of the gap serves \emph{\needGroupTop} needs; it would
most often ease newcomers' \emph{\barrierTopOne}.
\item \textbf{RQ3:} TF-IDF detects agent-only knowledge with F1 \detectorFOne{} (recall
\detectorRecall); sentence embeddings do no better.
\end{itemize}
\end{tcolorbox}

\section{Background}

\paragraph{Agent context files.} \texttt{CLAUDE.md} (Claude Code), \texttt{AGENTS.md} (a
tool-neutral convention first used by Codex) and Copilot's instructions file are loaded into every
agent session. Chatlatanagulchai et al.\ analysed 2{,}303 such files, derived 16 instruction
categories and found them hard to read~\cite{chatlatanagulchai2026agentreadmes};
Mohsenimofidi et al.\ studied how projects engineer this context~\cite{mohsenimofidi2026context};
Gloaguen et al.\ found the files help agents mostly when they carry project-specific
practice~\cite{gloaguen2026agentsmd}.

\paragraph{Newcomer onboarding.} READMEs describe what a project does and how to use
it~\cite{prana2019readme}; CONTRIBUTING files how to set up, test and submit changes. Dagenais et
al.\ describe the ``landscape'' a newcomer must learn~\cite{dagenais2010landscape} and Steinmacher
et al.\ the barriers newcomers face~\cite{steinmacher2015barriers,santos2024onboarding}. We use
both to interpret agent-only knowledge.

\section{Study Design}

\paragraph{Data and sample.} We start from the \nPackageFiles{} agent files of the Agent READMEs
dataset~\cite{chatlatanagulchai2026agentreadmes}. The dataset records each file's blob SHA, so we
recover its \emph{snapshot commit} (the newest commit with that blob) and take the README and
CONTRIBUTING at that commit, located as GitHub does. After the exclusions in
Table~\ref{tab:flow}, \nEligible{} files remain; we sample \nPerAgent{} per agent type (one per
repository), giving \nSampleRepos{} repositories. Overall estimates are post-stratified to the
eligible population.

\paragraph{Units.} Each document is split at its headings (H2/H3, and H1 when used for sections)
into \nUnits{} units; the \nAgentUnits{} agent units have a median of \agentUnitMedianWords{} words.
We code up to 10 random agent units per repository, \nQueued{} in all, weighted by the inverse
sampling fraction.

\paragraph{Coding.} Each unit gets (A)~its instruction categories~\cite{chatlatanagulchai2026agentreadmes};
(C)~its coverage in README and CONTRIBUTING --- \emph{agent-only}, \emph{partially covered},
\emph{shared} (paraphrases count, links elsewhere do not), or \emph{agent-directed} when it only
addresses the AI --- with the covering human sections as evidence; and, for agent-only and partial
units, (D1)~the newcomer need~\cite{dagenais2010landscape} and (D2)~the barriers it would
ease~\cite{steinmacher2015barriers,santos2024onboarding}. Coding used a tool showing the unit beside
the full human documentation, without any similarity ranking. For the pilot and main sets an LLM
(Claude) drafted each label and the author reviewed it against the documents: \nDraftsKept{} of
\nDraftsReviewed{} drafts (\draftKeepRate) kept their coverage and \nDraftsCorrected{} were
corrected. The \nReliabilityUnits{} units of the reliability set (\nReliabilityRepos{} repositories)
were coded blind, without drafts.

\paragraph{Analysis.} RQ1: per repository, the share of knowledge units (excluding agent-directed)
in each coverage class, averaged per agent, with 95\% CIs from 1{,}000 bootstrap draws resampling
repositories; category and agent effects via a logistic GEE clustered by
repository~\cite{liang1986gee}. RQ2: distribution of needs and barriers over gap units (agent-only
or partial). RQ3: each agent unit is scored against its README and CONTRIBUTING, item by item, with
TF-IDF and three sentence-embedding models~\cite{reimers2019sbert,xiao2023cpack,zhang2025qwen3embedding}\ifllmjudge,
and with an LLM judge~\cite{yang2025qwen3} on borderline scores\fi; thresholds are tuned on the
\nPilotRepos{} pilot repositories and evaluated on the rest.

\textbf{What is missing is how to work on the project} (Figure~\ref{fig:rq1}b): \catHighOne{}

\section{Discussion}

\paragraph{Projects onboard agents better than people.} The knowledge newcomers find hardest to
get --- commands, conventions, environment, architecture --- is written down, but in the file
addressed to the agent; what the project \emph{is} stays in the README.

\paragraph{Agent files are a ready source for contributor docs.} Maintainers can move agent-only
sections into CONTRIBUTING, and a lexical detector is enough to flag candidates. Copying is not
enough, though: agent files are harder to read than CONTRIBUTING files in \fleschHarderShare{} of
repositories (median Flesch \agentFlesch{} vs.\ \contribFlesch; Wilcoxon \fleschContribP).

\paragraph{Two documents drift apart.} Where they contradict each other, one is stale; running the
detector in CI could flag such drift along with new gaps.

\section{Threats to Validity}\label{sec:threats}

\paragraph{Construct.} We compare with README and CONTRIBUTING only; wikis, websites and
\texttt{docs/} are out of scope, which the \texttt{docs/} check bounds.
\paragraph{Internal.} \nDraftsReviewed{} of \nCodedUnits{} labels started from an LLM draft that
the author reviewed, so results may inherit the model's judgement; the \nDraftsCorrected{}
corrections bound rather than measure this.
\ifsecondcoder\ifsecondcoderllm
Agreement on the blind set is with an LLM annotator, which may share the drafting model's blind
spots; agreement between two human coders was not measured.
\fi\else
Coverage labels come from one annotator; inter-rater agreement is pending.
\fi
\paragraph{External.} Requiring a CONTRIBUTING file selects established projects (median
\sampleMedianStars{} stars); the files evolve quickly.

\section{Conclusion}

Projects tell their coding agents much that they do not tell their contributors:
\agentOnlyOverall{} of agent-file knowledge is agent-only and \anyGapOverall{} is not fully
available to people, mostly about how to work on the project. Because this knowledge already
exists in the repository, a simple detector can point maintainers to it.
